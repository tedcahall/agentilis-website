AI Agents That Remember: Picking Up Where They Left Off, Month After Month

In our own operations, AI agents work on long projects across many separate sessions. Each session used to start close to blank, so context had to be rebuilt and decisions explained again. In March 2026 we gave the agents a two-tier memory. A short curated index loads at the start of every session, and detail is kept in logs the agents can look up when they need it. Today 18 agents use it. A new session starts already knowing the open projects, the standing rules and the decisions made months ago.

What the Agents Do
  1. Read the memory index at the start of every session. It lists what the agent knows and which file to open for each topic
  2. Read the day's notes and confirm what they were last working on before picking the work back up
  3. Load topic files, such as the people they work with, the team and open threads, only when the task calls for them, so startup stays small
  4. Write decisions, preferences and findings to the day's notes as they happen, not at the end of the session
  5. Add raw detail to append-only logs during the session, so the detail is kept even after the core is trimmed
  6. Distill those logs into the curated core by updating it in place: current state, key facts and where things stand, never a growing list
  7. Record each standing rule with the date it was set, and follow it in every session after that
  8. Keep project facts in shared project files and personal context in the agent's own memory, so each kind of fact lives in one place
Guardrail

A person sets the rules, and the agents carry them forward. The curated core is edited in place and kept short, so it holds what is true now, not everything ever said. Raw detail goes to append-only logs, so the record is never rewritten. Personal or sensitive details stay in an agent's own memory and are kept out of shared files. The rollout only added files. Nothing the agents already had was changed.

Our Hypothesis

Why we think ours works better

This is a hypothesis, not a measured result. We have not run a side-by-side test. Built-in memory has real strengths: it needs no setup, it consolidates notes on its own, and its search finds notes by meaning even when the wording differs.

We think our approach works better for a team of agents on long-running work, for five reasons. First, a person decides what is durable, and every standing rule carries who set it and when, so an agent follows the latest instruction rather than a model's summary of it. Second, the index points to topic files that load only when needed, so the startup context stays small as memory grows, instead of one memory file reaching its budget and being cut short. Third, raw logs are append-only, so nothing is lost when the core is condensed. Fourth, one shared convention across the team makes handoffs and continuity consistent from one agent to the next. Fifth, it runs on top of the built-in memory search rather than replacing it. We keep the built-in nightly sweep and the automatic save before summaries turned off, so the core changes only when a person, or an agent following a person's rules, changes it.
