A Production MCP Server That Puts Company Intelligence in Every Agent's Hands

The company intelligence reports started as Python code run by hand, one company at a time, on one machine. Rebuilding the pipeline as a Model Context Protocol (MCP) server put it behind an agent. Now anyone on the team, in the US or Europe, asks for a report in plain language from a laptop or a phone, and the agent runs it, tracks it and delivers the finished PDF. The reports feed marketing materials, prospect research and a free 30-minute AI assessment call.

Why MCP
  • Agents can use it. MCP is the standard way for AI agents to call tools. Any MCP-capable agent can request a report, so the research is available to the whole agent team.
  • The reports go to work. Marketing materials, prospect research and preparation for the free 30-minute AI assessment call all draw on them.
  • Work happens in parallel. Several reports run at once, and nobody waits on one person or one machine.
  • Access from anywhere. A request typed into a phone chat is enough. The agent sends the finished report back in the same conversation.
How It Works
  1. A team member asks an agent for a report, in plain language, from a laptop or phone
  2. The agent calls the MCP server, which starts the job and returns a job ID immediately
  3. The server gathers the data from nine sources, has Claude write the analysis, and renders the report, using the same pipeline as the command line
  4. The agent checks the job status, then downloads the finished report
  5. The agent delivers the report back in the chat
  6. Any saved report can be re-rendered in another format in seconds, with no new research cost
Under the Hood
  • FastMCP 4, upgraded from version 3, serving MCP over streamable HTTP
  • Non-blocking jobs: a report runs in the background while the agent keeps working
  • Persistent job history that survives restarts, plus tools to list and download past reports
  • A model switch: Claude Opus 5.5 by default, with other models available per request
  • One pipeline core shared by the MCP server, the command line and the batch runner
Guardrail

Every call needs a secret token, except a basic health check, and rejected calls are logged without exposing the token. File downloads are tested against path-traversal attacks. A test fails if the MCP server, the command line and the batch runner ever drift apart, so a report from an agent is always the same report.
