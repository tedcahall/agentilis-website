The Situation

A system that worked, and a weekend chore that never went away.

In 2015, Ted built marrspoints.com, a cloud points scoring system for the Washington DC Region of the SCCA. It tracks every driver, class and race in the Mid-Atlantic Road Racing Series: eight race weekends in 2026, at Summit Point, NJMP, VIR and Mid-Ohio. In 2018 the region gave Ted its Regional Executive Award for building and running it.

The system worked. The work around it was the problem. After every race weekend, 27 official result files had to be renamed to the right format, uploaded one at a time through an admin tool, published, and confirmed. It took more than an hour each time, by hand. Behind it sat two Java applications that had been running for over a decade.

Rules vs. Judgment

Some of it has to be exact every time. Some of it takes a call.

Rules: exact, every time
  • Rename all 27 result files to the required format
  • Upload every file and publish the results
  • Score points the same way for every driver and class
  • Test every code change before it ships
  • Send a confirmation when the job is done
Judgment: a call on the fly
  • Process live results during the day, while racing is still going on
  • Handle gaps and imperfect data as they arrive
  • Tell provisional results from official ones
  • Process the official results after the race

The rules column is where agents are most dependable. The judgment column is the real test, and it is the job Inman does on every race weekend.

What We Did

Five agents, one system, managed from a phone.

  1. Max automated the back office.
    He receives the 27 result files by email, logs into the admin tool, renames and uploads every file, publishes the results and sends a confirmation. More than an hour of work became minutes.
  2. James upgraded the code.
    He refactored and upgraded the two Java applications, starting with 20,000 lines on day one, and has since added several new features.
  3. Watts tests everything.
    He wrote more than 60 Playwright and JUnit test cases. Every change James makes is tested before it goes live.
  4. Ken runs the infrastructure.
    He keeps the test environment and production on AWS running, deploys updates, and confirms each release with smoke tests.
  5. Inman runs race weekends.
    He manages the live results feed in the back-office tool during the day and processes the official results after the race.

Ted managed all of it from his phone, over Telegram.
